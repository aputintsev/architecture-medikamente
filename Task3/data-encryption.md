| Данные (Класс / Домен)                         | В чем необходимость защиты                                                                                                                                                                                                                   | Инструменты защиты                                                                                                                                                                                                                                                                                            |
|------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Медицинские данные (Диагнозы, анализы)         | 152-ФЗ ст. 10, 323-ФЗ (Врачебная тайна). Утечка грозит уголовной ответственностью. Требуется криптозащита класса КС1/КС2.                                                                                                                    | PostgreSQL TDE + pgcrypto (шифрование колонок). LUKS/dm-crypt на дисках. mTLS (Istio) между микросервисами. HashiCorp Vault для ключей.                                                                                                                                                                       |
| Сканы документов (паспорта, СНИЛС)             | Несанкционированный доступ к сканам документов позволяет украсть личность. Нарушение 152-ФЗ.                                                                                                                                                 | S3 SSE-C (шифрование ключом клиента). Pre-signed URLs с TTL 5 минут. WORM-политика для защиты от изменений.                                                                                                                                                                                                   |
| ПДн (ФИО, телефон, email)                      | Штрафы по КоАП. Необходимость разграничения доступа между врачами, ресепшеном и лабораторией.                                                                                                                                                | TLS 1.3 на всех внешних соединениях. Data Transformation Service для маскирования данных на фронтендах в соответствии с RBAC политикой. Keycloak (RBAC/ABAC).                                                                                                                                                 |
| Журнал записи на прием                         | Связка Пациент-Врач-Время является врачебной тайной. Раскрытие специализации врача раскрывает диагноз.                                                                                                                                       | PostgreSQL TDE. Row-Level Security в БД. Маскирование цели визита для ресепшена. Детерминированное шифрование связки ID врача и пациента. HMAC-индексы для поиска по телефону.                                                                                                                                |
| Данные обмена с лабораториями (Внешний контур) | Даже при использовании TLS, лаборатория получает данные в открытом виде и может хранить их у себя без шифрования. Лаборатория может перепутать результаты анализов пациентов, если полагаться только на ФИО.                                 | Data Minimization + Токенизация — замена ФИО на UUID направления. mTLS с клиентским сертификатом. JWS (JSON Web Signature) для проверки целостности. Если лаборатория присылает скан результата в PDF, он должен быть зашифрован паролем (пароль передается отдельным каналом или генерируется по алгоритму). |
| Финансовые данные (Платежи, договоры)          | Положение Банка России о защите информации при переводе денежных средств. Коммерческая тайна (суммы, номера договоров). Целостность отчетности.                                                                                              | VPN-туннель (WireGuard) между сервером 1С и ККМ. BitLocker на сервере 1С. Переход на облачную ККТ с TLS (в перспективе).                                                                                                                                                                                      |
| Данные ТМЦ и закупок (1С Торговля и склад)     | Коммерческая тайна (цены, поставщики). Искажение данных об остатках лекарств/материалов может привести к срыву операций (нечем делать анализы). Необходима защита от случайных или злонамеренных изменений. ПДн контрагентов в справочниках. | BitLocker на сервере 1С. Миграция на PostgreSQL + TDE. Выделение сервера 1С и рабочих мест склада в отдельный VLAN, изолированный от сегмента, где находятся сервисы для пациентов, с доступом только через VPN.                                                                                              |
| Аудиторские логи (ELK Stack)                   | Требование 152-ФЗ о регистрации событий доступа к ПДн. Логи должно быть нельзя удалить или изменить задним числом. Также в логах может содержаться чувствительная информация.                                                                | Шифрование индексов Elasticsearch. Альтернатива: VictoriaLogs с шифрованием на уровне диска. Filebeat TLS при отправке логов. WORM-хранилище для архивных логов. Elasticsearch Watcher для алертов на аномалии.                                                                                               |
| Секреты и ключи шифрования (Vault)             | Централизованное хранилище всех ключей шифрования, паролей БД и API-токенов. Компрометация Vault приведет к компрометации всей системы.                                                                                                      | Vault в режиме High Availability с Auto-Unseal через облачный KMS. Аудит всех запросов к Vault с алертами на подозрительную активность.                                                                                                                                                                       |
| Данные в Data Lake (Hadoop)                    | Риск утечки необезличенных данных при перемещении данных из операционных БД в озеро данных. При обучении ML-моделей недопустимо использовать реальные ФИО пациентов.                                                                         | NiFi EncryptContent Processor с ключами из Vault. Автоматическая токенизация PII до записи в Hadoop. Apache Ranger для тегирования и маскирования данных на входе в Hive. HDFS Transparent Encryption.                                                                                                        |
